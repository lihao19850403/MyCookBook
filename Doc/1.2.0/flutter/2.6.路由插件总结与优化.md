# 路由插件总结与优化

#### 总结

通过开发Flutter路由插件，可以发现：

1.  原生页面跳转至Flutter页面的场景中，Flutter页面内容也是通过原生页面承载的，这个页面是`FlutterIndexPage`，其中用来显示Flutter页面内容的控件是`FlutterPage`，此控件内部封装了`XComponent`。这个场景其实相当于两个原生页面之间的跳转。Flutter部分不需要通过特定的插件方法来控制页面跳转，使用一行dart代码即可拿到从原生页面传递过来的参数：

```text
var pathInfo = PlatformDispatcher.instance.defaultRouteName;
```

2.  Flutter页面跳转至其他页面的场景中，由于不知道目标页面是原生页面，还是另一个Flutter页面，因此需要使用插件方法来控制页面跳转。这里使用了一个go()方法对跳转动作进行了统一，如果目标页面还是一个Flutter页面，那么使用dart语句`Navigator.of(context).push()`即可原地跳转了；如果目标页面是原生页面，那么go()方法调用的路径是：

```text
[dart]FlutterRouter.go() → [dart]FlutterRouterPlatform.go() → [dart]MethodChannelFlutterRouter.go() → [HarmonyOS]FlutterRouterPlugin.onMethodCall()的go分支 → [HarmonyOS]FlutterRouterPlugin.routerPushHandler.call() → 跳转至具体的原生页面
```

3.  原生页面返回至Flutter页面的场景中，其实可以认为是两个原生页面之间进行的返回动作，只是原Flutter页面要顺路获取一下结果参数。这个场景中并没有特定的插件方法，原生页面进行返回的时候，调用之前跳转动作带过来的`MethodResult`类型参数，并调用其`success()`方法回传参数即可。

4.  Flutter页面返回至其他页面的场景中，与场景2类似，由于不知道上一个页面是原生页面，还是另一个Flutter页面，因此需要使用插件方法来控制页面返回。这里使用了一个back()方法对返回动作进行了统一，如果上一个页面还是一个Flutter页面，那么使用dart语句`Navigator.of(context).pop()`即可原地返回了；如果上一个页面是原生页面，那么back()方法调用的路径是：

```text
[dart]FlutterRouter.back() → [dart]FlutterRouterPlatform.back() → [dart]MethodChannelFlutterRouter.back() → [HarmonyOS]FlutterRouterPlugin.onMethodCall()的back分支 → [HarmonyOS]FlutterRouterPlugin.routerBackHandler.call() → 原生页面进行跳转
```

因此开发的路由插件主要是为Flutter页面发起的跳转或返回动作服务的。

#### 优化

##### 一、进一步封装路由插件

1.  在Flutter插件目录中的ohos工程里，FlutterRouterPlugin中的`routerPushHandler`和`routerBackHandler`都是static级别的，我们可以把它们降为private，并同时去掉`setRouterPushHandler`和`setRouterBackHandler`的static标记，使得两个handler变得私有化。修改完毕后进行`hflutter build har --release`操作。

2.  harmonyOS工程的入口EntryAbility中不再给FlutterRouterPlugin设置两个handler了，将对应的两行代码删除。

3.  Flutter插件管理类FlutterWrapEntry可修改为：

```text
import { FlutterEngine, FlutterEntry, Log } from "@ohos/flutter_ohos";
import { flutterRouterPlugin } from "./FlutterRouterUtils";

const TAG = "FlutterWrapEntry";

/**
 * Flutter模块与原生交互工具类，在此可以注册各种插件。
 * @author li.hao85
 */
export default class FlutterWrapEntry extends FlutterEntry {
  configureFlutterEngine(flutterEngine: FlutterEngine): void {
    super.configureFlutterEngine(flutterEngine);
    try {
      /* 注册通用插件。 */
      flutterEngine.getPlugins()?.add(flutterRouterPlugin());
      /* 注册其他插件。 */

      // this.delegate?.addPlugin(new BatteryPlugin());
    } catch (error) {
      Log.e(
        TAG,
        "Tried to register plugins with FlutterEngine ("
          + flutterEngine
          + ") failed.");
      Log.e(TAG, "Received exception while registering", error);
    }
  }
}
```

其中flutterRouterPlugin()方法内容如下：

```text
/** 鸿蒙平台下的Flutter路由管理handler。 */
export function flutterRouterPlugin(): FlutterRouterPlugin {
  let flutterRouterPlugin: FlutterRouterPlugin = new FlutterRouterPlugin();
  flutterRouterPlugin.setRouterPushHandler(flutterRouterPushHandler);
  flutterRouterPlugin.setRouterBackHandler(flutterRouterBackHandler);
  return flutterRouterPlugin;
}
```

之前EntryAbility中对两个handler的设置操作被移动到了这里。

##### 原因分析

一般的“页面返回”动作分如下几种情况：

- 用户通过操作页面元素返回上一页，比如单击返回按钮。这种场景下通过路由方法的调用即可正常返回。
- 用户从屏幕边沿向屏幕中心快速滑动，或者点击物理返回键，都会产生一个“物理返回”的动作。这种场景下承载这些Flutter页面的容器`FlutterIndexPage`在系统中被认为是一个单独的页面，系统的物理返回键只能作用在原生页面上，并不会进入到Flutter页面容器中起作用。

因此有必要对Flutter页面容器`FlutterIndexPage`进行改造，使之支持设备的物理返回动作。

##### 解决方案

整体思路是：当用户处于`FlutterIndexPage`页并按下物理返回键的时候，向Flutter页面发出通知，令其调用back()方法完成页面的返回。这是一个原生页面调用Flutter方法的动作，需要对Flutter路由插件进行改造。

1.  在Flutter路由插件FlutterRouterPlatform中，增加MethodChannel的获取方法声明：

```text
import 'package:flutter/services.dart';
import 'package:plugin_platform_interface/plugin_platform_interface.dart';

import 'flutter_router_method_channel.dart';

abstract class FlutterRouterPlatform extends PlatformInterface {
  ...
  MethodChannel getChannel() {
    throw UnimplementedError('getChannel() has not been implemented.');
  }
  ...
}
```

2.  在Flutter路由插件MethodChannelFlutterRouter中对此方法进行实现：

3.  Flutter路由插件的harmonyOS平台类FlutterRouterPlugin也需要增加MethodChannel的获取方法：

```text

/** FlutterRouterPlugin **/
```

4.  在Flutter路由插件FlutterRouter中，给这个MethodChannel增加方法调用监听：

```text
import 'package:flutter/material.dart';
import 'package:flutter/services.dart';
import 'package:flutter_router/router_manager.dart';

import 'flutter_router_platform_interface.dart';

class FlutterRouter {
  /// 初始化Flutter层方法回调监听。
  ///
  /// 参数[navigatorKey]可用来获取全局context。
  void initOnMethodCallWhenBuild(GlobalKey navigatorKey) {
    FlutterRouterPlatform.instance
        .getChannel()
        .setMethodCallHandler((MethodCall call) async {
      if (call.method == 'back') {
        back(navigatorKey.currentState!.context, params: call.arguments);
        return true;
      }
      return '${call.method} is not exist.';
    });
  }
  ...
}
```

5.  现在在Flutter插件的main.dart中，可以对此MethodChannel进行初始化了：

```text
import 'package:flutter/foundation.dart';
import 'package:flutter/material.dart';
import 'package:flutter_router/flutter_router.dart';
import 'package:flutter_router/router_manager.dart';
import 'package:my_cook_book_flutter_plugin/login_page.dart';
import 'package:my_cook_book_flutter_plugin/second_page.dart';
import 'package:my_cook_book_flutter_plugin/utils.dart';

void main() {
  _initRouters();
  var pathInfo = PlatformDispatcher.instance.defaultRouteName;
  runApp(MyApp(pathInfo: pathInfo));
}

class MyApp extends StatelessWidget {
  const MyApp({Key? key, required this.pathInfo}) : super(key: key);
  final String pathInfo;

  @override
  Widget build(BuildContext context) {
    FlutterRouter().initOnMethodCallWhenBuild(Global.navigatorkey);
    return MaterialApp(
      navigatorKey: Global.navigatorkey,
      theme: ThemeData(primarySwatch: Colors.blue),
      home: RouterManager.instance.getRouterWidget(pathInfo),
    );
  }
}

void _initRouters() {
  RouterManager.instance
      .addRouter('login_page', (params) => LoginPage(params: params));
  RouterManager.instance
      .addRouter('second_page', (params) => const SecondPage());
}

```

注：

- **必须在build方法中调用`FlutterRouter().initOnMethodCallWhenBuild()`！**
- 参数Global.navigatorkey可以使用一个专门的类来保存，比如这样：

```text
import 'package:flutter/widgets.dart';

class Global {
  /// 全局Navigator上下文。
  static GlobalKey<NavigatorState> navigatorkey = GlobalKey();
}
```

这样路由插件部分就改造好了，总结起来就是给Flutter插件增加了方法调用监听，使之能够接收原生平台传递过来的back()方法调用请求，并间接调用自己的back()方法完成页面返回动作。

6.  harmonyOS工程中的FlutterWrapEntry增加一个调用Flutter插件back()方法的入口：

```text
export default class FlutterWrapEntry extends FlutterEntry {
  // FlutterRouterPlugin可单独拿出来，之后会被调用。
  private flutterRouterPlugin: FlutterRouterPlugin = getFlutterRouterPlugin();

  configureFlutterEngine(flutterEngine: FlutterEngine): void {
    super.configureFlutterEngine(flutterEngine);
    try {
      /* 注册通用插件。 */
      flutterEngine.getPlugins()?.add(this.flutterRouterPlugin);
      /* 注册其他插件。 */

      // this.delegate?.addPlugin(new BatteryPlugin());
    } catch (error) {
      Log.e(
        TAG,
        "Tried to register plugins with FlutterEngine ("
          + flutterEngine
          + ") failed.");
      Log.e(TAG, "Received exception while registering", error);
    }
  }

  /**
   * 调用Flutter的back()方法。
   * @param params 方法参数。
   * @param callback 执行结果回调。
   */
  callFlutterBack(params?: Object, callback?: MethodResult) {
    this.flutterRouterPlugin.getChannel()?.invokeMethod('back', params, callback);
  }
}
```
